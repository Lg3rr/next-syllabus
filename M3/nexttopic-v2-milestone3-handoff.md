**Milestone:** Offline Syllabus Import Pipeline
**App:** Next Topic — NEET study tracker, offline-first
**Package ID:** `com.nexttopic.app`
**Status:** Compiles with zero errors ✓ (no new Gradle dependencies required)

## What Was Built

### Schema Decision (pre-implementation)

Source JSON (`syllabus_neet_11.json`, NEET Class 11: 4 subjects / 46 chapters / 567 topics) was
inspected before writing any code. Findings:

- Consistent keys at every level, unique string `id`s, no duplicates.
- `colorHex` exists only on subjects.
- `orderIndex` exists on subjects, chapters, and topics — not represented in the M2 entities.

Resolution (confirmed): added `orderIndex` to all three entities, `colorHex` to `SubjectEntity`
only. All list queries changed from `ORDER BY name ASC` to `ORDER BY orderIndex ASC` to preserve
curriculum order.

### Serialization Models (new)

`syllabus/SyllabusJson.kt` — `SyllabusJson`, `SubjectJson`, `ChapterJson`, `TopicJson`, matching
the JSON schema exactly. `class` (reserved word) mapped via `@SerialName("class") val classLevel`.

### Asset Data Source (new)

`syllabus/SyllabusAssetDataSource` — reads `assets/syllabus.json`, decodes with
`kotlinx.serialization.json.Json`, returns `Result<SyllabusJson>`. Catches `IOException` and
`SerializationException` explicitly; no exceptions escape.

### Mapping Layer (new)

`syllabus/SyllabusMappers.kt` — `SubjectMapper`, `ChapterMapper`, `TopicMapper`, each a stateless
`object` with one `toEntity()` function. Chapter/Topic mappers take the parent's generated `Long`
id as a parameter, since JSON nesting doesn't carry Room's autogenerated FK.

### Seeder (new)

`syllabus/SyllabusSeeder` — `seedIfNeeded()`:
1. `SubjectDao.getCount()` — if > 0, returns immediately (already imported).
2. Loads and parses the asset.
3. Inserts subjects → chapters → topics, threading generated parent ids down, inside a single
   `AppDatabase.withTransaction { }` block — all-or-nothing, so a crash mid-import leaves no
   partial rows.
4. Returns `Result<Unit>`; `NextTopicApp` logs failure, never crashes the app.

### Repository / DAO changes

- `SubjectDao` / `SubjectRepository` / `SubjectRepositoryImpl` — added `getCount(): Int`.
- All three DAOs — list queries now `ORDER BY orderIndex ASC`.
- No new repository methods needed for insert (existing `insert()` reused).

### Entities (modified)

```kotlin
data class SubjectEntity(id: Long = 0, name: String, colorHex: String, orderIndex: Int)
data class ChapterEntity(id: Long = 0, subjectId: Long, name: String, orderIndex: Int)
data class TopicEntity(id: Long = 0, chapterId: Long, name: String, orderIndex: Int)
```

### Wiring (modified)

`NextTopicApp.onCreate()` launches `syllabusSeeder.seedIfNeeded()` on an application-scoped
`CoroutineScope(SupervisorJob())`. This is the only trigger point — no UI, no ViewModel calls it.

### Dependency Injection

No new Hilt modules. `SyllabusAssetDataSource` and `SyllabusSeeder` use `@Inject constructor` and
resolve automatically from `SingletonComponent`; `SyllabusSeeder` is `@Singleton`.

### Asset

`app/src/main/assets/syllabus.json` — the provided NEET Class 11 JSON, copied verbatim (not
regenerated, not restructured).

## Duplicate Prevention

Single guard: `SubjectDao.getCount() > 0` short-circuits the entire seeder before any parsing or
insert happens. No per-row existence checks — the transaction guarantees the table is either
fully empty or fully seeded, so a table-level count is sufficient and cheaper than an
externalId-based per-row check.

## Manual Steps

None. No new Gradle dependencies (`room-ktx`, already present, provides `withTransaction`).

## Known Gap — Flag for M4

JSON string `id`s (e.g. `phy_ch1_t1`) are **not** persisted anywhere — Room uses autogenerated
`Long` primary keys only. Fine for this milestone (no feature reads by JSON id yet). If M4
(progress tracking, weak topics, etc.) needs a stable reference that survives a syllabus
re-import, add an indexed `externalId: String` column to the three entities and populate it in
the mappers before building on top of it.
